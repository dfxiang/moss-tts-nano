# 用户资料与头像

本文说明已实现的用户资料、自助改密、管理员重置密码和头像能力。接口参数与响应以
[API 接口文档](API接口文档.md)和 Swagger UI 为准。

## 1. 功能范围

| 能力 | 说明 |
| --- | --- |
| 用户资料 | 显示名称、电话号码、电子邮件；显示名称必填，默认取用户名 |
| 个人资料 | 登录用户可维护自己的显示名称、电话和邮箱，用户名只读 |
| 自助改密 | 校验原密码，新密码输入两次；成功后保留当前会话 |
| 管理员重置密码 | 拥有 `system:user:manage` 权限的账号可为其他用户设置新密码 |
| 头像 | 用户上传、更换或恢复默认头像；头像存放在对象存储中 |

用户名、启用状态、角色和员工关联不属于自助修改范围。

## 2. 数据模型

`users` 表使用以下字段：

| 字段 | 说明 |
| --- | --- |
| `display_name` | 显示名称，非空；存量数据启动时回填为 `username` |
| `phone` | 电话号码，可为空 |
| `email` | 电子邮件，可为空；当前不要求唯一 |
| `avatar_key` | 对象存储中的头像键，可为空 |
| `avatar_url` | 由 `avatar_key` 派生的只读值；未设置时返回默认头像地址 |

## 3. 接口

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| `PUT` | `/api/auth/me` | 登录 | 更新本人的资料 |
| `PUT` | `/api/auth/me/password` | 登录 | 校验原密码后修改密码 |
| `PUT` | `/api/auth/me/avatar` | 登录 | 上传并更新本人头像 |
| `DELETE` | `/api/auth/me/avatar` | 登录 | 恢复默认头像 |
| `GET` | `/api/avatars/{filename}` | 匿名 | 读取默认头像或用户头像 |
| `POST` | `/api/users/{user_id}/reset-password` | `system:user:manage` | 管理员重置密码 |

自助接口只作用于当前登录用户，不接受目标用户 ID，避免通过参数修改他人资料。

## 4. 校验、权限与审计

### 4.1 管理与自助边界

- 管理员建号和修改资料继续使用既有的系统用户权限；
- 维护本人资料、密码和头像只要求有效登录令牌，不新增权限编码；
- 自助接口只作用于当前登录用户，不接受目标用户 ID。

### 4.2 自助改密

用户需提供原密码、新密码和确认密码；新密码为 6 至 100 个字符且两次输入必须一致。
修改成功后当前会话继续有效。

### 4.3 管理员重置密码

管理员重置密码不校验原密码，也不提供二次确认，只允许拥有
`system:user:manage` 权限的账号调用。

### 4.4 审计

资料修改、改密、重置密码和头像变更均写入操作日志。日志不记录密码、头像文件名或对象键。

### 4.5 字段规则

- `display_name` 最长 50 个字符，去除首尾空白后不能为空；
- `phone` 最长 30 个字符，只允许数字、`+`、`-`、空格和括号；
- `email` 最长 100 个字符，执行基础格式校验；
- 电话和邮箱允许清空，清空后保存为 `NULL`。

### 4.6 已知边界

- JWT 为无状态令牌，改密后其他已签发令牌在过期前仍然有效；如需立即失效，
  应另行引入令牌版本或统一轮换 `JWT_SECRET`；
- 当前不提供邮箱验证、邮箱找回密码、密码复杂度策略和登录限流；
- 管理员重置密码不需要再次输入原密码，也不提供前端二次确认。

## 5. 头像处理与安全边界

### 5.1 存储

- 头像只保存到 S3 / MinIO，数据库只保存 `avatar_key`；
- 默认头像键为 `avatar/default.png`，用户头像键为
  `avatar/u{用户ID}-{随机数}.png`；
- 随机文件名使头像更新后自然获得新 URL，可使用长缓存而不必手动清理浏览器缓存；
- 旧头像删除失败只记录告警，不会阻塞资料更新。

### 5.2 上传流程

1. 客户端先检查扩展名与 1MB 上限，提供即时反馈；
2. 服务端重新检查文件大小并按实际图片内容解码；
3. 图片居中裁切并缩放为 256×256，去除 EXIF 等元数据后统一编码为 PNG；
4. 先写入新对象，再更新数据库；成功后尽力删除旧对象。

### 5.3 图片校验

- 文件上限 1MB，扩展名和实际解码结果都必须符合图片格式；
- 支持的输入为 JPEG、PNG、BMP、WebP 和 GIF；
- 设置像素上限，防止超大图片造成内存耗尽；
- GIF 只保留首帧；输出统一为 256×256 PNG。

### 5.4 匿名读取

浏览器加载 `<img>` 时无法附加 `Authorization` 请求头，因此头像读取接口允许匿名访问。
该接口同时执行两项限制：

1. 文件名必须匹配 `default.png` 或 `u{数字}-{32位十六进制}.png`；
2. 服务端固定只读取 `avatar/` 前缀，调用方不能指定其他对象键。

任何不符合条件的请求统一返回 404，避免把同一个 bucket 中的 GSP 证照扫描件暴露为
任意对象下载。头像响应使用 `image/png`、长缓存、`ETag` 和 `nosniff`。

## 6. 验证

```bash
cd api && .venv/bin/python -m pytest -q
cd frontend && npm run build
cd frontend && npx playwright test
cd frontend && npx playwright test --config playwright.live.config.ts
```

运行环境用例位于 `frontend/tests/live/user-profile.spec.ts`，覆盖资料修改、管理员重置密码、
头像上传/恢复和自助改密，并在结束后清理测试数据。
