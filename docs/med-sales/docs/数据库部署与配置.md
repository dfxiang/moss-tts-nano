# 数据库部署与配置

本文说明本项目对 PostgreSQL 的要求、容器化与本机安装两种落地方式、字符集与中文排序规则的配置方法，
以及迁移、备份和常见问题的处理。演示数据的建库/造数脚本见 [db/README.md](../db/README.md)。

## 一、要求一览

| 项目 | 要求 | 本项目默认值 |
| --- | --- | --- |
| 版本 | PostgreSQL **17**（15+ 即可，但 15 以下不支持把 ICU 作为库级默认排序规则） | 镜像 `postgres:17` |
| 字符集 | `UTF8` | `UTF8` |
| 排序规则 | 中文按**拼音**排序 | ICU 排序规则 `zh-u-co-pinyin` |
| 时区 | 与使用方一致（本项目按中国区部署） | `Asia/Shanghai` |
| 库名 / 用户 | 可自定义 | `medsalesdb` / `postgres` |
| 端口（宿主机） | 可自定义 | `5688` → 容器 `5432` |
| 扩展 | 无（不依赖任何 PG 扩展） | — |

如果只记一件事：**字符集 UTF8 + 排序规则用 ICU 的 `zh-u-co-pinyin`**。这两项必须在建库（initdb）时定好，
事后要改只能重建数据库。

## 二、为什么必须配中文排序

系统里大量列表和报表按名称排序（客户、商品、员工、供应商……都是 `ORDER BY name`）。
PostgreSQL 默认的 `C` / `en_US` 排序规则对汉字是按 **Unicode 码点**比较，业务上看起来就是乱序：

```
C 排序（错误示例）：周 < 安 < 张三 < 李四 < 欧阳小明 < 王五 < 赵六 < 陈七
拼音排序（期望）  ：安 < 陈七 < 李四 < 欧阳小明 < 王五 < 张三 < 赵六 < 周
```

拼音排序下，客户名单打印出来是「安…陈…李…欧…王…张…赵…周」，和通讯录、纸质台账的顺序一致，
业务人员找起来才顺手。项目统一使用 ICU 的 `zh-u-co-pinyin`：它是 CLDR 的中文拼音顺序，
不依赖宿主机是否装了中文 locale，换机器结果一致。

## 三、方式一：Docker Compose（推荐）

仓库根目录的 `docker-compose.yml` 自带数据库，无需额外准备：

```bash
docker compose up -d medsales-db        # 只起数据库
docker compose up -d --build            # 起整套（数据库 + 后端 + 前端 + 对象存储）
```

数据库容器的关键配置（见 `docker-compose.yml`）：

```yaml
medsales-db:
  image: postgres:17
  environment:
    TZ: ${TZ:-Asia/Shanghai}
    POSTGRES_USER: ${POSTGRES_USER:-postgres}
    POSTGRES_PASSWORD: ${POSTGRES_PASSWORD:-pass01!}
    POSTGRES_DB: ${POSTGRES_DB:-medsalesdb}
    # UTF-8 + 中文拼音排序，只在数据卷为空时（首次 initdb）生效
    POSTGRES_INITDB_ARGS: ${POSTGRES_INITDB_ARGS:---locale-provider=icu --icu-locale=zh-u-co-pinyin --encoding=UTF8}
  ports:
    - "${MEDSALES_DB_PORT:-5688}:5432"
  volumes:
    - medsales-db-data:/var/lib/postgresql/data
```

`POSTGRES_INITDB_ARGS` 里两个参数的来历：

| 参数 | 作用 |
| --- | --- |
| `--locale-provider=icu` | 排序交给 ICU。官方 Debian 镜像已用 ICU 编译，可用 `select count(*) from pg_collation where collprovider='i'` 确认不为 0 |
| `--icu-locale=zh-u-co-pinyin` | 中文按拼音排序（`zh` 的 CLDR 默认就是拼音，这里显式写全，便于日后排查） |

### 验证

```bash
# 1) 库级设置：datlocprovider 应为 i（ICU），datlocale 应为 zh-u-co-pinyin
docker exec medsales-db psql -U postgres -tAc \
  "select datname, datlocale, datlocprovider, pg_encoding_to_char(encoding) from pg_database;"

# 2) 排序实测：应输出 安 < 陈七 < 李四 < 欧阳小明 < 王五 < 张三 < 赵六 < 周
docker exec medsales-db psql -U postgres -tAc \
  "select string_agg(n,' < ' order by n) from
   (values ('张三'),('李四'),('王五'),('赵六'),('陈七'),('欧阳小明'),('安'),('周')) t(n);"

# 3) 时区
docker exec medsales-db psql -U postgres -tAc "show timezone; select now();"
```

> `pg_database.datlocale` / `pg_collation.colllocale` 是 PostgreSQL 17 的列名，
> PostgreSQL 15 / 16 上对应的是 `daticulocale` / `colliculocale`。

### 改默认值时注意

`POSTGRES_INITDB_ARGS`、`POSTGRES_PASSWORD`、`POSTGRES_DB` 以及库级 `TZ` 都**只在数据卷为空时**生效。
改完要重建数据卷（**会清空数据库，先备份**）：

```bash
docker compose stop medsales-db
docker compose rm -sf medsales-db
docker volume rm med-sales_medsales-db-data      # 卷名 = <compose 项目名>_medsales-db-data
docker compose up -d medsales-db
docker compose exec medsales-api python scripts/create_admin.py --username admin --password 你的密码
cd db && MEDSALESDB_PORT=5688 .venv/bin/python run_all.py      # 重新造数
```

> ⚠️ 不要用 `docker compose down -v` 图省事：它会删掉本项目**所有**卷，包括存证照扫描件的
> `medsales-minio-data`。按卷精确删除更安全。

### 已有库改时区（无需重建）

时区是运行参数，可以在运行的实例上直接改，只影响之后写入的数据：

```bash
docker exec medsales-db psql -U postgres -c "ALTER SYSTEM SET timezone TO 'Asia/Shanghai';"
docker exec medsales-db psql -U postgres -tAc "SELECT pg_reload_conf();"
```

### 连接方式

| 场景 | 主机 | 端口 | 说明 |
| --- | --- | --- | --- |
| 容器里的后端 | `medsales-db` | `5432` | 走 compose 网络 `medsales`，见 `DATABASE_URL` |
| 宿主机上的脚本/客户端 | `127.0.0.1` | `5688` | `db/` 造数脚本的默认值；端口被占用时用 `MEDSALESDB_PORT` 改 |

## 四、方式二：自己封装镜像

官方 `postgres:17` 已经满足要求（ICU 内置），一般不需要自己封装。两种例外：

**1）离线 / 内网环境**：把镜像带过去即可，配置不用改。

```bash
docker pull postgres:17
docker save postgres:17 | gzip > postgres17.tar.gz     # 目标机执行：docker load -i postgres17.tar.gz
```

**2）坚持用 glibc 的 `zh_CN.UTF-8` 排序规则**（老一代国产 PG 镜像都是这个路子，多数常用汉字
也按拼音排列，但与 ICU 的细则不完全一致，例如多音字、中英混排、Unicode 版本差异）。需要自己生成 locale：

```dockerfile
# 文件名：Dockerfile.db
FROM postgres:17
RUN apt-get update \
 && apt-get install -y --no-install-recommends locales \
 && localedef -i zh_CN -f UTF-8 -c zh_CN.UTF-8 \
 && rm -rf /var/lib/apt/lists/*
ENV LANG=zh_CN.UTF-8 LC_ALL=zh_CN.UTF-8
```

```bash
docker build -f Dockerfile.db -t medsales-db:zh .
```

然后在 compose 里把 `image: postgres:17` 换成 `image: medsales-db:zh`，initdb 参数改成：

```yaml
POSTGRES_INITDB_ARGS: "--locale=zh_CN.UTF-8 --encoding=UTF8"
```

> 一个库只能有一种默认排序规则。**同一套数据不要在两种规则之间来回搬**：文本索引会绑定排序规则，
> 跨规则恢复可能报 `collation ... does not exist` / `collation mismatch`，排序结果也会变。
> 选定一种，开发/测试/生产保持一致。

## 五、方式三：不用 Docker，本机安装

### 5.1 安装 PostgreSQL 17

**Ubuntu / Debian**（PGDG 官方源）：

```bash
sudo install -d /usr/share/postgresql-common/pgdg
sudo curl -fsSL -o /usr/share/postgresql-common/pgdg/apt.postgresql.org.asc \
  https://www.postgresql.org/media/keys/ACCC4CF8.asc
echo "deb [signed-by=/usr/share/postgresql-common/pgdg/apt.postgresql.org.asc] \
https://apt.postgresql.org/pub/repos/apt $(lsb_release -cs)-pgdg main" \
  | sudo tee /etc/apt/sources.list.d/pgdg.list
sudo apt update && sudo apt install -y postgresql-17
```

**RHEL / Rocky / Alma Linux**：

```bash
sudo dnf install -y https://download.postgresql.org/pub/repos/yum/reporpms/EL-9-x86_64/pgdg-redhat-repo-latest.noarch.rpm
sudo dnf -qy module disable postgresql
sudo dnf install -y postgresql17-server
sudo /usr/pgsql-17/bin/postgresql-17-setup initdb
sudo systemctl enable --now postgresql-17
```

**macOS（Homebrew）**：

```bash
brew install postgresql@17
brew services start postgresql@17
```

### 5.2 用 ICU 初始化集群（推荐）

```bash
# 先确认这个发行版的 PostgreSQL 是用 ICU 编译的
pg_config --configure | tr ' ' '\n' | grep icu        # 能看到 --with-icu

initdb -D /var/lib/pgsql/17/data \
  --locale-provider=icu \
  --icu-locale=zh-u-co-pinyin \
  --encoding=UTF8
```

### 5.3 或者用 glibc 的 zh_CN.UTF-8

```bash
sudo localedef -i zh_CN -f UTF-8 zh_CN.UTF-8          # 系统没有该 locale 时先生成
initdb -D /var/lib/pgsql/17/data --locale=zh_CN.UTF-8 --encoding=UTF8
```

### 5.4 已有实例：不改集群也能用拼音排序

集群默认排序规则是初始化时定死的，但可以按库、按列、按表达式指定：

```sql
-- 新建库时直接指定（PG15+）
CREATE DATABASE medsalesdb
  TEMPLATE template0 ENCODING 'UTF8'
  LOCALE_PROVIDER icu ICU_LOCALE 'zh-u-co-pinyin';

-- 也可以自己定义排序规则（PG 自带 zh-x-icu，与上面的等价）
CREATE COLLATION zh_pinyin (provider = icu, locale = 'zh-u-co-pinyin');

-- 使用：表达式级 / 列级
SELECT name FROM customer ORDER BY name COLLATE "zh-x-icu";
ALTER TABLE customer ALTER COLUMN name TYPE varchar(120) COLLATE zh_pinyin;   -- 会重建相关索引
```

本项目 SQL 里不带 `COLLATE`，走的是**库默认**排序规则，所以建库时指对就够；
如果现网库默认排序是 `C`/`en_US` 又不便重建，可以给参与排序的列逐个 `ALTER ... COLLATE`。

### 5.5 初始化业务库

```bash
export DATABASE_URL=postgresql+asyncpg://postgres:你的口令@127.0.0.1:5432/medsalesdb
cd db && python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python run_all.py          # 建库 + 造数 + 校验；加 --reset 重建
```

随后启动后端（`docker compose up -d --build` 或本机 `uvicorn`）。用户、角色、权限、审计日志、
证照、批次等系统表由 API 启动时自动补齐，不需要手工建表。

## 六、接入已有的 PostgreSQL

不必使用自带容器，把连接串指过去即可：

```bash
# 方式 A：统一连接串（推荐，模板见 .env.example）
DATABASE_URL=postgresql+asyncpg://用户:口令@数据库主机:5432/medsalesdb

# 方式 B：db/ 造数脚本用的独立变量
MEDSALESDB_HOST=... MEDSALESDB_PORT=... MEDSALESDB_USER=... MEDSALESDB_PASSWORD=... MEDSALESDB_NAME=...
```

接入前请对照第一节逐项确认，尤其是**字符集与排序规则**：排序规则不对，功能都能跑，
但列表顺序会不对，而且很难事后补救。

## 七、备份与恢复

```bash
# 备份（自定义格式，含结构、数据与注释）
docker exec medsales-db pg_dump -U postgres -d medsalesdb -Fc -f /tmp/medsalesdb.dump
docker cp medsales-db:/tmp/medsalesdb.dump ./

# 恢复到新库（推荐；直接覆盖原库需要 --clean --if-exists）
docker exec medsales-db psql -U postgres -c \
  "CREATE DATABASE medsalesdb_new TEMPLATE template0 ENCODING 'UTF8' LOCALE_PROVIDER icu ICU_LOCALE 'zh-u-co-pinyin'"
docker cp medsalesdb.dump medsales-db:/tmp/
docker exec medsales-db pg_restore -U postgres -d medsalesdb_new -Fc /tmp/medsalesdb.dump
```

要点：

- **目标库的编码与排序规则要和源库一致**，否则可能恢复报错，或恢复后排序与索引行为不同；
- 别忘了对象存储里的证照扫描件与头像（MinIO 卷 `medsales-minio-data`）要一起备份；
- 卷级冷备份（一致性最好，先停容器）：
  `docker run --rm -v med-sales_medsales-db-data:/data -v "$PWD":/backup alpine tar czf /backup/db-vol.tgz -C /data .`

## 八、常见问题

**Q：报 `initdb: error: invalid locale name "zh_CN.UTF-8"`**
镜像或系统里没有这个 locale。要么改用 ICU（本文推荐，不依赖系统 locale），要么先
`apt-get install -y locales && localedef -i zh_CN -f UTF-8 zh_CN.UTF-8`。

**Q：中文顺序看着不对，或者中英文混排时顺序怪**
先确认库的排序规则：`select datlocale, datlocprovider from pg_database;`，再确认查询里没有显式
`COLLATE "C"`。另外，`zh` 排序规则会把汉字排在拉丁字母**之后**，与「英文优先」的直觉不同，属于预期行为。

**Q：能不能把已有库的排序规则改掉？**
库级默认值不能改，只能重建库再导入；或按列/表达式指定排序规则（会重建相关索引）。

**Q：加了 ICU 排序会不会变慢？**
ICU 排序比 `C` 慢一些，这是排序规则的固有成本。本项目的排序都发生在分页后的小结果集上，
影响可忽略；将来若有按名称排序的大数据量场景，可以给排序列建带相同排序规则的索引。

**Q：前缀模糊查询（`LIKE '药%'`）能用上索引吗？**
非 `C` 排序规则下，普通 btree 索引对 `LIKE '前缀%'` 的优化不够稳定。需要的话给对应列加
`text_pattern_ops` 索引，它与排序规则无关：

```sql
CREATE INDEX idx_customer_name_pattern ON customer (name text_pattern_ops);
```

（本项目当前只对商品名称建了普通索引 `idx_product_name`，用于等值匹配与排序。）

**Q：`now()` 落库的时间和我看到的不一样？**
本项目的时间列是 `TIMESTAMP`（不带时区），`now()` 按**会话时区**转成墙钟时间后落库。
compose 已把容器时区设为 `Asia/Shanghai`；换库或改时区时注意**新老数据会混用两种时区**，
要么保持不动，要么统一迁移。应用侧 `date.today()`（今日销售额、应收账龄、证照到期天数）
同样依赖容器时区——这就是把 `TZ` 写进 compose 的原因。

**Q：`create_admin.py` 报关系不存在？**
先让 API 至少启动过一次（系统表由它兜底创建）再执行；脚本本身也会调用 `init_db()`。
